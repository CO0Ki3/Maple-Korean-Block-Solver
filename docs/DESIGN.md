# 한글 모아모아 솔버 v2 — 설계 문서

작성일: 2026-10-02. 대상 이벤트: 메이플스토리 「한글 모아모아」 (2026-10-01 10:00 ~ 10-14 23:59).
이전 버전: https://github.com/CO0Ki3/Maple-Korean-Block-Solver (단일 HTML, 빔 서치, 최고 14만 점).

## 1. 목표

- 이벤트 규칙을 **빠짐없이** 시뮬레이터에 넣는다 (실제 점수표, 능력 생성·한도·소멸, 점 찍기·바꿔 뽑기, 종료 조건, 50만 점 캡).
- 한 판 점수를 최대화하는 의사결정 엔진을 만든다. 탐색 + 학습된 평가 함수가 기본이고, 학습(자기대전 기반 정책 탐색/TD)으로 평가 함수를 보강한다.
- 브라우저에서 동작하는 솔버 UI를 만든다 (판·손패 입력, 스크린샷 인식, 추천 배치, 회전·반전 안내, 판 이어가기).
- 속도가 필요하면 WASM(+워커 병렬, SIMD)으로, 그래도 모자라면 WebGPU로 샘플링 롤아웃을 가속한다.

## 2. 규칙 명세 (구현 기준)

- 조각의 빈 칸(ㅁ의 가운데 등)은 판에서 이미 채워져 있어도 상관없다. 조각이 차지하는 칸만 비어 있으면 된다.

### 2.2 손패와 등장 확률
- 한 번에 3개가 등장하고 3개를 모두 배치해야 새 3개가 등장한다. 배치 순서는 자유.
- 각 조각은 **가중치 테이블**(관측 횟수 기반, 사용자 조정 가능)에서 독립적으로 뽑힌다고 가정한다. 단계(누적 제거 줄 수)별 확률 변화는 모델링하지 않는다 (사용자 결정). 기본값은 균등.

### 2.3 배치와 줄 제거
- 배치 즉시 조각 칸 수만큼 점수.
- 배치 후 가득 찬 가로줄이 있으면 동시에 제거. 세로줄은 제거되지 않는다. 중력이 없으므로 제거된 줄은 그냥 비워진다.
- 동시 제거 줄 수 n에 따라 300·n² 점: 1줄 300, 2줄 1,200, 3줄 2,700, 4줄 4,800, 5줄 7,500. 조각 최대 높이가 5이므로 한 번에 최대 5줄.

### 2.4 능력
- 조각 배치 횟수가 7의 배수가 될 때마다 빈 칸 한 곳에 능력 아이콘이 생성된다. 종류는 점 찍기 40%, 바꿔 뽑기 60%. 점 찍기로 칸을 채우는 것은 배치 횟수에 포함되지 않는다.
- 아이콘이 있는 줄을 제거하면 해당 능력을 획득하고 50점을 얻는다.
- 보유 능력은 두 종류 합산 최대 7개. 7개를 보유 중이면 새 아이콘이 생성되지 않고, 아이콘이 있는 줄을 제거해도 획득되지 않으며 아이콘은 판에 그대로 남는다.
- 판 위 아이콘은 최대 3개. 4번째가 생성되면 가장 먼저 생성된 아이콘부터 사라진다.
- 점 찍기: 원하는 빈 칸 1칸을 채운다. 이것으로 줄이 제거되면 점수와 능력 획득이 정상적으로 일어난다 (사용자 확인).
- 바꿔 뽑기: 보유 조각 중 하나를 즉시 다른 조각으로 바꾼다. 결과 조각은 가중치 테이블에서 뽑힌다 (사용자 확인: 즉시 교체).

### 2.5 종료와 캡
- 시간 제한 없음. 회전·반전을 모두 고려해도 남은 손패 중 어느 것도 놓을 수 없고, 보유 능력이 0개일 때 종료.
- 한 판 최대 500,000점. 캡에 닿으면 종료로 취급한다.
- 랭킹은 한 판 최고 점수. 「다시 시작」은 점수를 기록하고 새 판을 연다. 따라서 초반이 나쁘면 다시 시작하는 것도 전략이다.

### 2.6 가정 (페이지에 명시되지 않아 확인이 필요한 것)
- A1. 아이콘 생성 위치는 아이콘이 없는 빈 칸 중 균등 랜덤.
- A2. 7개 보유 중이라 생성이 건너뛰어진 경우에도 배치 카운터는 계속 돌고, 다음 7의 배수에서 다시 시도한다.
- A3. 바꿔 뽑기 결과가 같은 조각일 수도 있다.
- A4. 점 찍기로 아이콘이 있는 칸을 채울 수 있다 (아이콘은 줄이 제거될 때까지 남는다).
- A5. 한 번의 제거로 여러 아이콘 줄이 지워지고 보유 한도를 넘기면, 먼저 생성된 아이콘부터 획득하고 나머지는 판에 남는다.

## 3. 아키텍처

```
moamoa/
├─ Cargo.toml                워크스페이스
├─ crates/
│  ├─ engine/                규칙·상태·탐색·평가·특징 (no_std 친화, 순수 Rust)
│  ├─ cli/                   네이티브 바이너리: selfplay / bench / train(CEM) / export-weights
│  └─ wasm/                  wasm-bindgen 바인딩 (엔진을 그대로 노출)
├─ web/                      Vite + TypeScript UI
│  ├─ src/ui/                판 편집, 손패, 능력, 추천 단계, 설정
│  ├─ src/vision/            스크린샷 인식 (격자 검출, 칸 분류, 손패 카드, 아이콘)
│  ├─ src/worker/            WASM 탐색 워커 풀 (루트 수 분할 병렬)
│  └─ public/pkg/            wasm-pack 산출물
└─ docs/
```

- 규칙은 `engine` 한 곳에만 있다. 학습(네이티브)과 실전(WASM)이 같은 코드를 쓴다.
- 판은 행당 `u16` 비트마스크 16개. 조각 방향은 사전 계산한 행 마스크(최대 높이 5). 배치 가능 검사는 시프트·AND, 줄 제거는 `== 0x3FF` 비교.
- 난수는 `SplitMix64/Xoshiro` 자체 구현 (wasm·네이티브 동일 시드 재현).

## 4. 알고리즘

### 4.1 상태와 행동
- 상태: 판 비트, 손패 3슬롯(비었음/조각 id), 점 찍기 수, 바꿔 뽑기 수, 아이콘 ≤3개(위치·종류·생성 순서), 배치 카운터(mod 7), 누적 줄, 점수.
- 행동: 배치(조각, 방향, 행, 열) / 점 찍기(행, 열) / 바꿔 뽑기(슬롯).
- 확률 노드: 새 손패 추첨, 바꿔 뽑기 결과, 아이콘 생성(위치·종류).

### 4.2 의사결정 탐색
1. **손패 내 완전 탐색(빔)**: 남은 조각들의 배치 순서와 위치를 레벨별로 전개한다. 각 레벨에서 `(판, 사용 마스크, 능력 수)`로 중복 제거 후 `보상 누적 + V(판)` 상위 B개만 유지. 점 찍기는 레벨 사이에 끼울 수 있는 행동으로 포함하되 한 탐색당 상한을 둔다.
2. **리프 평가**: 손패를 다 놓은 상태의 가치 = 누적 보상(실제 점수) + V(afterstate). V는 학습된 평가 함수.
3. **다음 손패 샘플링 lookahead(옵션)**: 상위 K개 리프에 대해 가중치 분포에서 손패를 M개 샘플링해 얕은 탐색을 돌리고 평균을 더한다. 조각이 들어가지 않을 위험을 직접 측정한다. WASM 워커 병렬로 돌린다.
4. **바꿔 뽑기 기대값**: 슬롯 i를 바꿨을 때 기대값 = Σ_p w_p · (조각 p로 바꾼 손패의 최선 가치). 현재 손패의 가치 및 능력 1개의 보험 가치와 비교해 추천한다. 보유 7개(캡)일 때는 사용이 사실상 공짜(생성이 막혀 있음)라는 점을 반영한다.
5. 게임 종료 회피: 어떤 배치도 불가능한 상태는 V = −∞ 취급, 능력 보유 수는 생존 보험으로 평가에 들어간다.

### 4.3 평가 함수 특징 (초기안, 가중치는 학습으로 결정)
- 채워진 칸 수, 비어 있지 않은 줄 수
- 가로/세로 전이 수 (들쭉날쭉함)
- 고립 빈 칸 수 (사방이 막힌 1칸)
- 빈 칸 연결 성분 수, 크기 ≤ 2인 성분 수 (조각으로 메우기 어려운 조각난 공간)
- 가중 커버리지 기반 사각(死角) 점수: 각 빈 칸을 덮을 수 있는 조각의 가중치 합이 작을수록 벌점
- 조각별 「놓을 자리 없음」 위험: 가중치 합
- 줄 완성도 히스토그램: 빈 칸이 1개/2개/3개인 줄 수
- 다중 제거 잠재력: 어떤 열을 기준으로 「그 열만 비어 있는 줄」이 연속으로 이어진 최대 길이 n (ㅣ로 300·n²), 2열 패턴(ㅌ·ㄹ·ㅑ 등) 포함
- 아이콘 관련: 보유 < 7일 때 아이콘 줄의 채움 정도, 아이콘 개수(3개 포화 시 소멸 위험)
- 보유 능력 수(점 찍기·바꿔 뽑기 별도, 체감하는 효용)

### 4.4 학습
- 1차: **교차 엔트로피 방법(CEM/CMA-ES)** 으로 선형 가중치를 자기대전 평균 점수 기준으로 최적화. 세대마다 공통 난수 시드로 분산을 줄이고, 학습용 탐색은 가벼운 설정(빔 10~20)으로 돌린다. 12코어 병렬.
- 2차(옵션): 리프 평가를 **N-tuple 네트워크 + TD(λ)** 또는 소형 CNN 가치망으로 교체. 탐색 구조는 그대로 두고 V만 바꾼다.
- 평가 지표: 고정 시드 100판의 평균·중앙값·사망 전 줄 수, 다중 제거 비율. 이전 솔버의 14만 점이 기준선.

## 5. 가속
- WASM: `wasm-pack --release`, `opt-level=3`, `wasm-opt -O3`. 비트 연산 중심이라 네이티브 대비 1.5~3배 느린 수준으로 예상.
- 병렬: 루트 후보(첫 배치)를 워커 N개에 분배. SharedArrayBuffer 없이 메시지 기반으로 충분.
- SIMD: 행 마스크 16개를 `u16x16`로 묶어 배치 검사·전이 계산을 벡터화 (필요 시).
- WebGPU: 리프별 손패 샘플링 롤아웃을 컴퓨트 셰이더로 돌리는 용도로 보류. 1~2초 안에 답이 나오면 도입하지 않는다.

## 6. 마일스톤
1. 엔진 + 규칙 테스트 (페이지 문구 하나당 테스트 하나) + 자기대전 CLI로 기준 점수 측정
2. 탐색 고도화 (점 찍기 행동, 바꿔 뽑기 기대값, 샘플링 lookahead) + CEM 학습 파이프라인
3. WASM 빌드 + 웹 UI (수동 입력, 추천, 적용, 되돌리기, 설정)
4. 스크린샷 인식 이식·개선, 조각 가중치 학습 UI
5. 규칙 적합성 감사(이벤트 페이지 대조), 성능 프로파일링, 필요 시 SIMD/WebGPU

## 7. 미결 사항
- 회전 버튼 방향(시계/반시계)과 반전 축(좌우/상하): 설정으로 두고 기본값은 이전 버전과 같이 시계·좌우.
- 조각 가중치 초기값: 이전 솔버의 출현 횟수 데이터가 있으면 가져온다. 없으면 균등.

## 8. 구현 현황 (2026-10-02)

- 엔진: 2장 규칙 전부 구현. `crates/engine/tests/rules.rs`에 페이지 문구 단위 테스트 26개(규칙 감사에서 확인된 결함의 회귀 테스트 포함). 발견한 모델링 공백 1건(4번째 아이콘 생성 시 최고령 아이콘 소멸을 탐색이 몰라 계획이 깨짐)은 소멸을 결정적 전이(`place_det`)로 옮겨 해결.
- 탐색: 손패 내 빔 서치 + 점 찍기 행동 + 바꿔 뽑기 기대값 + 다음 손패 샘플링 lookahead(엔진 내부, 또는 UI에서 후보별 워커 병렬). 감사 후 보강: 남은 조각이 못 들어가는 노드에 벌점(빔이 유일한 완전 배치를 버리던 문제), 불완전 계획이면 빔 4배로 재시도, lookahead 공통 난수, 점 찍기만으로 구조하는 부분 계획 반환. 네이티브 2.1M 노드/초, wasm 탐색 30~80ms(빔 64).
- 학습: CEM. best.json은 세대별 공통 시드가 아니라 고정 검증 시드(`--val-games`)로 고른다. 1차(40세대, 120손패 제한) 결과 `weights/trained.json`. 3차(200손패, 2차 best에서 시작)의 최종 평균이 현재 `weights/trained.json` (96판 합산 평균 330,796, 2차 best 295,106). 감사 수정 후 엔진·48판 고정 시드·빔 32 기준 기본 가중치 평균 203,383 → 322,598, 중앙값 188,122 → 330,106. 탐색 설정은 다음 손패 샘플링이 가장 큰 이득이며, 2차 비교(cem3 가중치)에서 빔 64 + 샘플 4 + 상위 후보 추가 샘플 8이 24판 전부 캡 도달·평균 650손패로 최선이라 솔버 기본값으로 삼았다. 표: `weights/README.md`.
- UI: 판·손패·아이콘 입력, 스크린샷 인식(원본 알고리즘 이식, 합성 데이터 1,190건 출력 일치), 추천 단계(회전·반전 횟수·위치·줄 점수), 적용·되돌리기, 바꿔 뽑기 분석, 설정. 헤드리스 Chrome(CDP) 스크립트로 전 흐름 검증.
- 시뮬레이터: 엔진의 `policy_step`(네이티브 자기대전과 동일)을 wasm으로 호출해 한 수씩 애니메이션하거나 최고 속도로 끝까지 두는 탭. 여러 판 일괄 실행(워커 병렬)으로 점수 분포를 본다.
- 보류: WebGPU(현재 속도로 불필요), 단계별 확률(사용자 결정으로 미사용).
- 스크린샷 인식 개선: 선택된(노란 배경) 손패 카드도 읽는다(원본은 흰 카드만). 실제 게임 캡처로는 아직 검증 전이며, 안 맞으면 수동 보정 경로를 쓴다.
