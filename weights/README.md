→ k=1이 전 판 캡 도달을 유지하는 가장 빠른 설정. k≥2는 평균이 낮아 보여도 사망 때문이며, 생존 판 기준으로는 k=1보다 빠르지 않다.

4차 CEM (편향 k=1을 켠 자기대전으로 재학습, cem3-latest에서 시작) 비교 — 빔 64 · 샘플 4 · 상위 8 · k=1:

| 가중치 | 시드 300~323: 캡 / 평균 손패 | 시드 400~423: 캡 / 평균 손패 / 평균 점수 |
|---|---|---|
| cem3-latest (= trained.json) | 24/24 / 629 | 21/24 / 590 / 471,100 |
| cem4-latest | 24/24 / 622 | 21/24 / 599 / 477,417 |
| cem4-best (검증 시드 최고) | 23/24 / 619 (1판 495,331 사망) | (미측정) |

→ 48판 합산 캡 도달 45/48로 동일, 손패·점수 차이는 1% 안팎(잡음 범위). 편향을 켠 재학습은 뚜렷한 이득이 없어 trained.json은 cem3-latest 유지 (2026-10-03). cem4-latest.json은 보관.
참고: 시드 400대에서는 두 가중치 모두 3판이 캡에 못 닿아, 이 설정(샘플 4)의 실제 캡 도달률은 24/24가 아니라 약 94%로 보는 게 맞다. UI 기본값은 샘플 8이라 더 안전하다.

결론: 빔 64 + 샘플 4 + 상위 후보 추가 샘플 8이 전 판 캡 도달 중 캡까지 손패가 가장 적고 다중 제거 비율이 가장 높으며 비용도 가장 싸다. 솔버 UI 기본값은 여기서 여유를 둔 **빔 64 + 샘플 8 + 상위 후보 8** (v2.1.0, 사용자 결정). 시뮬레이터는 속도 때문에 샘플 0이 기본이고 설정에서 켤 수 있다.
`web/public/weights/trained.json`은 UI가 시작할 때 자동으로 읽는다. 새 학습 결과가 더 좋으면 `scripts/publish-weights.sh`로 두 곳을 같이 바꾼다. 학습 로그와 세대별 가중치는 `weights/runs/<이름>/`에 쌓인다 (git 제외).

평가 함수 교체 실험(N-tuple, TD/MC/증류)은 모두 선형 평가를 넘지 못했다. 표와 해석은 `docs/DESIGN.md` 9장. 실험 산출물은 `weights/runs/td-smoke`, `distill1`, `distill2` (git 제외).
