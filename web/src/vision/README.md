# vision — 스크린샷 인식

원본 `block-solver.html`의 스크린샷 인식 루틴을 알고리즘·임계값 변경 없이 TypeScript로 옮긴 모듈이다. DOM 의존은 `ImageData` 타입뿐이다.

## 파이프라인
1. `prepImage` — 픽셀마다 밝기(`lum`)와 색 분류 비트(`cls`: 1 청록, 2 흰색, 4 채도 있는 색)를 계산한다.
2. `detectBoard` — 청록 픽셀 중 이웃보다 어두운 점(격자선 후보)을 열·행별로 세고, `fitAxis`로 격자 원점(x0, y0)과 칸 간격(p, q)을 맞춘다. 선명도(`vis`)와 선/칸 대비로 신뢰 여부(`conf`)를 정한다.
3. `classifyCells` — 칸 안쪽(0.14~0.86)을 샘플링해 청록·흰색·경계·밝기 편차·평균색을 구하고, 행별 빈칸 기준색(평평한 청록 칸의 중앙값)과 비교해 채움/빈칸과 능력 아이콘(⊙ 점찍기, ⇄ 바꿔뽑기)을 판정한다.
4. `detectHand` — 흰 카드를 연결 성분으로 찾고, 카드 안 블럭 색 픽셀의 경계 상자에서 칸 크기를 추정해 블럭 모양(`cells`)을 읽는다.
5. `recognize` / `recognizeWithRect` — 위 단계를 묶은 진입점. `recognize`는 자동 검출이 불확실하면 저장된 보정값(`cal`)을 쓰고, 그것도 안 맞으면 `ok: false`를 돌려준다. 그때 호출 측이 직접 지정한 사각형으로 `recognizeWithRect`를 부른다.

## 주의
- 이미지는 긴 변 `MAX_IMAGE_SIDE`(2400px) 이하로 호출자가 먼저 줄여서 넘긴다. 이 모듈은 축소하지 않으며, 보정값의 `iw`/`ih`도 줄인 뒤의 크기다.
- 색상 범위, 0.28/0.45, 0.14/0.86, `DL=6`, `2.5*cp` 등 모든 임계값은 원작자의 화면(해상도·테마)에서 맞춘 값이다. 다른 기기·해상도에서는 빗나갈 수 있으니 바꾸기 전에 실제 캡처로 확인할 것.
- 손패는 3장 미만이 나올 수 있고, 모양을 못 읽은 카드는 `cells`가 없거나 `null`이다.
- 주석 중 `/* */` 형태의 두 곳(행별 기준색, 능력 아이콘 판정)만 원본 그대로이고, 나머지 주석은 이식하면서 덧붙였다.
- 원본과 다른 점 하나: 선택된(노란 배경) 손패 카드도 읽도록 `CLS_PALE`(연노랑) 비트를 추가했다. 카드 배경 탐색에만 쓰고 칸 분류·아이콘 판정에는 쓰지 않는다. 이벤트 페이지의 게임 화면에서 선택 카드(ㅂ)와 일반 카드(ㅏ)가 함께 인식되는 것을 확인했다.
